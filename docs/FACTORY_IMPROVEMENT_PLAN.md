# Plano de melhoria da factory

## Objetivo

Fazer a descoberta produzir uma base factual confiável com o menor número de perguntas necessárias, sem perder segurança de publicação.

## Etapas

| Etapa | Situação | Resultado esperado |
|---|---|---|
| 1. Definir classes de fonte e autoridade | aplicada em 0.5.0 | dossiês, assets, canais oficiais, evidências públicas e hipóteses recebem tratamentos distintos |
| 2. Filtrar pendências por impacto | aplicada em 0.5.0 | só permanecem lacunas desconhecidas, não resolvíveis no escopo e materialmente relevantes |
| 3. Separar descoberta de estratégia | aplicada em 0.5.0 | prioridade, arquitetura, copy e direção criativa seguem para a Fase 2A |
| 4. Exigir revisão avaliadora antes do fechamento | aplicada em 0.5.0 | confirmações são propagadas e perguntas redundantes são removidas |
| 5. Criar casos de regressão de descoberta | próxima melhoria | exemplos reais medem se a factory continua calibrada em novos clientes |
| 6. Migrar clientes existentes seletivamente | contínua | cada projeto recebe o padrão sem sobrescrever decisões, conteúdo ou identidade próprios |

## Critério de sucesso

Uma descoberta é considerada calibrada quando o usuário consegue revisar rapidamente os fatos, os materiais e as poucas lacunas restantes, sem precisar reexplicar informações já autorizadas. A quantidade de pendências não tem meta fixa; a qualidade é medida pela relevância e pela resolubilidade de cada linha.

## Caso de referência

Um projeto recente de escritório de advocacia mostrou a falha que este plano corrige: a primeira versão abriu 21 perguntas, incluindo decisões da Fase 2A e confirmações já disponíveis em fontes autorizadas; a revisão humana reduziu a lista para duas lacunas materiais. Esse caso deve orientar os futuros testes de regressão sem carregar fatos específicos do cliente para a factory.
