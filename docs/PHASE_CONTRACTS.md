# Contratos de fase

## Fase 0 — Diagnóstico

Entrada: plano e projeto existente. Saída: diagnóstico, inventário, riscos e decisão provisória de stack. Sem alteração de código.

## Fase 1 — Governança

Entrada: Fase 0 aprovada. Saída: documentos de contexto, cliente, assets, decisões, pendências e configuração da factory. Sem alterar layout, catálogo ou stack.

## Fase 2 — Arquitetura de conteúdo

Só iniciar com aprovação. Separar dados do catálogo e definir contratos de conteúdo sem trocar o comportamento visual por acidente.

## Fase 3+ — Implementação

Cada mudança deve declarar escopo, impacto, teste e critério de aceite. Migração de stack exige aprovação independente.
